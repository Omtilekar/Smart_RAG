Storage & artifact layers

Text corpus

EDGAR-CORPUS filings, normalized to Markdown/YAML frontmatter, then chunked.

Vector index

LanceDB, exact cosine search, metadata pre-filtering support.

Retrieval cache

Exact-query, in-process LRU + TTL cache for dense retrieval evidence only.

XBRL store

DuckDB (data/xbrl.duckdb) holding structured financial facts and submissions.

Model / provider layer

Embedding model + a config-driven, provider-neutral generation interface.

Live runtime vs. production artifact

The dense route you can query from Chat now runs against the full production corpus (Qwen3-Embedding-0.6B, 10,487,096 rows). One gap remains and is shown here, not hidden: unscoped searches are slow until the metadata pre-filter is wired into the live router.

What has already been built offline

Remaining gate: route company and year filters into the production retriever (unscoped exact search measured about 33 s per query). Real AWS deployment is deferred until this and the rest of the local production-readiness gates pass — see the Roadmap page.
